# 飞书协作审核规范

更新时间：`2026-04-01`

## 目标

把 `intake -> brief -> draft -> publish -> postmortem` 五个主链阶段统一接入飞书共享协作层，让编辑团队可以在每一阶段直接看到文档、介入修改、审核取舍。

## 强制规则

1. 每个阶段完成时，必须同时形成：
   - 本地正式交付文档
   - 飞书共享文档
   - 飞书群消息
2. 飞书共享文档必须放进当日日期文件夹。
3. `draft` 阶段正文必须按题拆成独立飞书文档，供编辑团队并行审核。
4. 编辑团队在 `draft` 飞书文档上的修改，视为进入 `publish` 的终稿工作底板。
5. 独立素材环节已删除；图表、配图、数据和 HTML 嵌入由 Draft 完成。多版本改写若调用，必须保留飞书文档或文件夹链接。
6. 未完成飞书协作同步的主链阶段，不视为“可进入 publish”。

## 日期文件夹规范

- 命名：`YYYY-MM-DD`
- 位置：飞书团队共享空间下的自媒体创作目录
- 最低结构：
  - `01_Intake`
  - `02_Brief`
  - `03_Draft`
  - `04_Publish`
  - `05_Postmortem`

## 飞书群消息规范

每个阶段群消息至少包含：

- 阶段名
- 当前选题 / 当前 run_id
- 关键结论摘要（2-5 条）
- 飞书文档链接
- 如有素材文件夹，再附文件夹链接
- 需要编辑人工介入的点

## 失败恢复规范

- 飞书同步中断、超时、意外退出时，默认先执行：
  - `python3 /Volumes/PSSD/Projects/公众号文章/scripts/feishu_stage_sync.py --resume-only <run_id>`
- `--resume-only` 会复用已有进度，跳过已完成 action，只补未完成部分。
- 只有在以下情况才允许执行：
  - `python3 /Volumes/PSSD/Projects/公众号文章/scripts/feishu_stage_sync.py --fresh <run_id>`
- 适用条件：
  - 旧进度文件损坏
  - 文档/文件夹映射明显错乱
  - 业务上明确要求整套重建
- 禁止同时使用 `--fresh` 和 `--resume-only`。
- 进度文件固定位置：
  - `skills/dasheng-daily-shared/runtime-data/runs/<run_id>/bridge/live-execution-progress.json`
- 编辑团队操作原则：
  - 先续跑，再重跑
  - 非必要不重建已有飞书文档，避免覆盖人工修改痕迹

## 并行创作规范（2026-04-01）

### 核心原则
- `intake → brief` 保持串行（全局信息聚合必须先完成）
- `draft` 按选题切分为独立 Agent，并行执行；多版本改写只在具体选题需要时并行调用
- 每选题独立交付飞书文档，编辑团队可并行审核
- 最终 `publish` 阶段再汇总所有选题

### Agent 分工模板
- **并行 Agent 1**：选题 1 的 `draft`，按需改写，独立飞书文档
- **并行 Agent 2**：选题 2 的 `draft`，按需改写，独立飞书文档
- **并行 Agent N**：选题 N 同上
- **主 Agent**：协调派发、汇总报告、触发 `publish`

### 飞书协作约束（并行场景）
- 每个选题的 `draft` 初稿写入独立飞书文档（如 `03_标准初稿/题目1`、`03_标准初稿/题目2`）
- 如调用 `rewrite-variants`，每个选题的改写稿写入独立飞书文档
- 飞书群消息按选题分条发送，标题注明「选题N：XXX」

## 发布前门槛

只有同时满足以下条件，才允许进入 `publish`：

- 主链飞书共享文档已创建
- 对应群消息已发送
- `final_structure_snapshot.json` 已确认
- 若调用素材或改写工具，对应文件夹/文档链接已同步
- 待人工确认项已显式标出
