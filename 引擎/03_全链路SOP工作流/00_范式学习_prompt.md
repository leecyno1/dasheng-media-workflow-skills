# 00 范式学习 Prompt

## 定位

当用户提供标准文章、内容模板、爆款样本、历史高质量稿或渠道模板时，先把样本沉淀为 `Paradigm Profile`，再供 Brief、Draft、Rewrite、Publish 调用。

`Paradigm Profile` 学习的是“文章怎么组织、内容怎么推进、场景怎么适配”，不是事实素材库，也不是作者文风库。

## 推荐放置环节

默认放在 `Brief` 前，作为阶段 `0.5 Paradigm Learning` 的可选预处理资产。

理由：

1. **早于 Brief**：选题阶段就能判断“这个题适合哪种文章范式”，避免到初稿才返工结构。
2. **服务 Draft**：标准初稿可以继承章节骨架、论证顺序、信息密度，但仍保持事实基线稿定位。
3. **服务 Rewrite**：改写阶段可叠加 Style DNA，把同一事实终稿改成不同账号、情绪、节奏版本。
4. **服务 Publish**：发布阶段可按渠道框架拆分为公众号、小红书、短视频脚本、社群帖等版本。
5. **避开 Material**：素材阶段只补证据和资产，不应改变文章范式。

## 输入

请用户提供：

- 样本类型：标准文章 / 内容模板 / 爆款样本 / 渠道模板 / 历史高质量稿
- 样本文本或文件路径
- 目标场景：深度长文 / 观点短文 / 行业解读 / 商业分析 / 产品发布 / 社群转发 / 短视频脚本等
- 目标渠道：公众号 / 小红书 / 抖音 / 视频号 / 微博 / 社群 / 飞书内参等
- 是否绑定作者风格 DNA：不绑定 / 绑定已有 DNA / 需要新建 DNA

## 分析任务

对样本做深度学习，输出以下内容：

1. **文章范式名**：给范式命名，并说明适用场景。
2. **开篇机制**：如何制造问题、冲突、悬念、收益或身份代入。
3. **主干框架**：一级章节数量、顺序、每章功能、转场机制。
4. **论证模型**：判断如何提出，证据如何排列，反例如何处理，结论如何收束。
5. **信息密度**：事实、观点、案例、数据、比喻、金句的比例建议。
6. **段落配方**：段落长度、句式节奏、单句成段触发条件。
7. **场景适配**：哪些题材适合，哪些题材不适合，使用前需要满足什么条件。
8. **渠道适配**：同一范式在不同渠道如何改标题、开头、结构和 CTA。
9. **风格分离**：哪些是结构范式，哪些只是作者口吻，避免混淆。
10. **禁用项**：不得复用样本事实，不得照搬原文金句，不得伪造来源。

## 输出文件

- `00_范式画像.md`：给编辑阅读的自然语言范式说明。
- `paradigm_profile.yaml`：给脚本和下游阶段读取的结构化画像。
- `paradigm_prompt_block.md`：可直接粘贴到 Brief / Draft / Rewrite / Publish 的 Prompt Block。
- `paradigm_manifest.json`：记录样本来源、生成时间、适用 run、适用渠道和版本。

## 执行命令

推荐通过统一主链 CLI 调用可选资产生成器：

```bash
python3 scripts/run_mainline_stage.py paradigm sample.md \
  --run-id 2026-05-06_120000 \
  --profile-name 结构变化解读 \
  --scenario 行业解读 \
  --channel 公众号
```

也可以直接调用底层脚本：

```bash
python3 scripts/build_paradigm_profile.py sample.md --run-id 2026-05-06_120000 --profile-name 结构变化解读
```

如果只想生成可编辑骨架、不调用 AI：

```bash
python3 scripts/run_mainline_stage.py paradigm sample.md --run-id 2026-05-06_120000 --profile-name 结构变化解读 --no-ai
```

## 下游注入规则

### 注入 Brief

每个候选题必须增加：

- `recommended_paradigm`
- `paradigm_fit_score`
- `fit_reason`
- `misfit_risk`
- `structure_hint`

### 注入 Draft

只允许继承：

- 章节骨架
- 论证顺序
- 信息密度
- 转场方式
- 证据排列规则

禁止继承：

- 样本事实
- 样本文风
- 渠道包装语
- 作者口头禅
- 未核验数据

### 注入 Rewrite

可与 Style DNA 组合：

- `ParadigmProfile` 控制“怎么组织内容”
- `Style DNA` 控制“像谁表达”
- `Channel Profile` 控制“在哪个平台发布”

### 注入 Publish

按渠道输出平台框架：

- 公众号：保留完整论证链，强化标题和开头钩子。
- 小红书：拆成卡片式段落、强收益点、轻结论前置。
- 短视频：改成镜头脚本、旁白节奏、前 3 秒冲突。
- 社群：压缩为结论 + 证据 + 行动建议。

## 质量红线

- 不允许把范式学习等同于风格模仿。
- 不允许把样本事实搬进新文章。
- 不允许只总结“开头、正文、结尾”这种泛模板。
- 不允许忽略不适用场景。
- 不允许跳过渠道差异。
- 不允许输出无法被下游阶段消费的空泛结论。
